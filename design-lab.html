01SOCIAL SYSTEM / 경제·정보 설계

정상적인 행동을
의심의 근거로 만드는 방법

사이비 교단 마피아 게임은 시민이 자기 진영의 승리를 위해 활동자금을 모으지만, 그 정상적인 행동이 잠입 교인의 행동과 비슷하게 보이도록 설계했습니다.

상태시스템 기획 · 시뮬레이션 및 프로토타입 작업 / 다인 실플레이 검증 미확인

→
행동 목격정체 불확실
→
강제 교화오판 시 양측 탈락
기획 의도

시민이 단순히 투표를 기다리는 수동적 진영이 아니라, 자금을 써서 직접 공격할 수 있게 합니다. 오판을 막는 것보다 합리적인 의심과 위험한 선택 사이의 긴장을 목표로 합니다.

핵심 규칙

시민 미션은 실제 공동 종교자금을 올리고, 잠입 미션은 빼앗습니다. 표시 금액은 자동 갱신되지 않아 직접 단말을 조회해야 합니다. 시민이 일반 시민에게 강제 교화를 사용하면 시전자와 대상 모두 탈락합니다.

실제 자금과 표시 자금이 달라지는 구조

INTERACTIVE EXAMPLE / 포트폴리오용 규칙 설명
서버상의 실제 공동자금 변화 예시0만 원
마지막 단말 조회 기준 표시값0만 원

이 위젯은 게임 화면이 아닌 설명용 시연입니다. 실제 규칙에는 단말 갱신 제한이 있으며, 시민에게 실제 값이 상시 공개되는 것은 아닙니다.

검증 필요

가상 에이전트 시뮬레이션에서 나타난 오판·목격·승률이 실제 사람의 심리전에서도 재현되는지는 확인되지 않았습니다. 한 번의 행동만으로 잠입 여부가 확정되지 않도록 설계한 의도를 실제 플레이로 시험해야 합니다.

검토한 요소

위험 지역의 보고를 무시하거나 전달하지 않는 간부, 개인 생존을 위한 전향 가능성, 비용을 감수하고 특정 정보의 불확실성을 줄이는 ‘봉인해제’ 수단 등을 논의했습니다.

자료 상태

이 페이지는 과거 대화에서 검토한 시스템 방향만 소개합니다. 간부 행동 확률, 봉인해제 비용, 전향 조건 등이 확정·구현됐다고 주장하지 않으며, 상세 수치·판정은 원본 기획서 대조 전까지 공개하지 않습니다.

03SKILL LOGIC / 연계 판정

5개 라인의 자동 전투,
인접 스킬을 하나의 결과로

각 라인에 배치된 캐릭터가 자동 공격하고, 이웃한 라인의 스킬 상태가 조건을 만족하면 연계 공격을 실행하는 구조를 기획했습니다.

상태과거 전투·스킬 규칙 설계 / 실제 게임 구현 및 플레이 테스트 미확인
LINE 01자동 전투

LINE 03활성 스킬 B
LINE 04자동 전투
LINE 05자동 전투

라인 2·3을 강조한 연계 판정의 설명용 도식. 실제 게임 스크린샷이나 확정 캐릭터 조합이 아닙니다.

기본 스킬 활성→인접 조건 확인→재료 스킬 소모→연계 스킬 생성
기획 의도

개별 캐릭터의 성능만 강화하는 것이 아니라, 인접 배치와 스킬이 맞물리는 순간을 전략으로 만들고자 했습니다.

예외·우선순위

연계에 사용된 하위 스킬은 소모되고, 연계 결과는 새로운 지속시간을 갖습니다. 생성된 연계 스킬도 더 높은 단계의 재료가 될 수 있으며, 상위 연계가 성립하면 하위 연계를 대체하고 최종 공격만 실행하도록 정했습니다.

검증 필요

연계의 발생 빈도, 스킬 가독성, 특정 캐릭터 조합의 과도한 효율은 실제 플레이 데이터로 검증하지 않았습니다. 시스템 설계와 판정 순서의 사례로 사용합니다.

04COMBAT RULE SPEC / 스냅샷·예외 처리

공격이 시작된 뒤
능력치가 바뀐다면?

뱀서류 전투 기획에서는 최대 세 무기를 순환 사용하면서, 공격과 스킬의 판정 시점을 구체적으로 정의했습니다. 모호한 구현 순서가 결과를 바꾸지 않도록 하는 것이 목적이었습니다.

상태시스템 상세 기획서 존재 / 실제 게임 구현·플레이 검증 자료 없음

이미 발동한 스킬은 저장된 100을 끝까지 사용. 다음 공격부터 120을 적용.

무기 교체 규칙

현재 무기의 마지막 탄창을 소비해도 즉시 교체하지 않습니다. 그 마지막 공격이 종료된 시점에 다음 무기로 넘어가도록 순서를 고정했습니다.

스킬 상태 보존

스킬 발동 시점의 무기 능력치를 저장합니다. 발동 후 무기를 바꾸거나 업그레이드해도 이미 실행 중인 스킬의 기준값은 변하지 않습니다.

기획 자료의 범위

무기·성장 시스템 기획서에 상세 처리 순서가 기록되어 있습니다. 다만 이를 구현 후 재현 테스트까지 완료한 성과라고 표현하지 않습니다.

05BALANCE PROBLEM / 대응 가능성

난이도가 높은 것과
대응이 불가능한 것은 다릅니다.

버블 기반 전투를 기획하면서, 서로 다른 색의 구슬이 소량씩 남는 배치 때문에 공격예고를 막을 수도, 몬스터를 처치할 수도 없는 상황이 반복된다는 문제를 발견했습니다.

상태규칙·몬스터 보드 데이터 존재 / 수정 후 플레이 결과는 미확인
발사 가능한 색 ≠ 필요한 색남은 보드를 지울 수 없음공격예고를 상쇄하지 못함턴 경과로 피해 누적

실제 특정 스테이지 배치가 아닌, 발견한 문제를 단순화한 설명용 도식입니다.

문제 정의

플레이어가 조준을 잘못해서가 아니라, 유효한 선택지가 부족한 상태에서 피해를 강제로 받는 경우가 많았습니다. 플레이어의 판단과 결과의 연결이 약해지는 문제가 있었습니다.

검토한 개선 방향

몬스터 HP만 낮추는 대신 공격예고와 구슬 배치, 고립 낙하 가능성, 공격력을 함께 재검토했습니다. 실제 효과는 수정 전후 결과가 없어 결론 내리지 않았습니다.

기획상 교훈

실패가 자주 발생한다는 수치만으로 난이도를 평가하지 않고, 플레이어에게 불리한 상황을 바꿀 합리적인 선택지가 있었는지를 확인해야 합니다.
